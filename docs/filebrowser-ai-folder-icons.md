# File Browser Local-Model Folder Icons

The Snowbridge File Browser fork can give each folder in the web listing an
icon picked by a local model. The feature is off by default and only exists in
the fork image; the stock upstream image ignores its settings.

Suggestions are generated by the host's crew-chief Ollama service. No external
API or key is involved. The model receives a folder name and up to 20 names of
its direct children. It does not receive file contents, host paths, usernames,
or file metadata.

## How it works

```text
Clockwork daily timer
  └─► local prefetch helper ─► authenticated File Browser prefetch API
                                  └─► folder icon service
                                        └─► unix socket relay ─► central ECU gate ─► Ollama

Browser listing ─► cached manual override, else cached model suggestion
```

- The browser's `GET /api/foldericons/<dir>` only reads the cache. Navigation
  never starts inference or waits for the model. New folders use the regular
  folder icon until a scheduled prefetch has picked them.
- The scheduler calls `POST /api/foldericons/prefetch`. It walks the
  authenticated File Browser user's visible directories and generates at most 40 missing
  picks per run, in batches of 10. Later runs advance through the uncached
  folders. It skips symlink directories and follows File Browser rules and
  hidden-file settings.
- In JSON-auth mode, use a dedicated read-only scheduler account with the same
  File Browser `Scope` and visibility rules as the normal browser account. In
  `private-vpn-mtls` mode, the host scheduler uses a dedicated mTLS client
  certificate; Caddy maps it to the existing `snowbridge` proxy user. The
  cache is keyed by scope and folder path, so generated suggestions are visible
  to users with that scope. Manual overrides are shared by users with the same
  scope.
- AI suggestions and manual choices are stored separately. A manual choice
  always wins for that scope and folder, including when inference is already
  in flight. **Use AI suggestion** removes the manual override and reveals the
  existing AI suggestion; if none exists, the folder keeps its default icon
  until a scheduled run fills it.
- Existing `folder-icons.json` entries are migrated to the separate AI and
  manual keys when the service next starts.
- The local-model request carries `X-ECU-Priority: batch`. The central ECU
  gate holds it while higher-priority GPU activity is active. The Clockwork
  timer owns when the prefetch process starts; it does not wrap the Ollama
  request in `ecu run`, which could stop the Ollama service the request needs.
- The model may only choose from a curated set of Material icons. The server
  validates every result, and the color follows the icon category. Renaming
  or moving a folder gives it a fresh path and therefore a new suggestion.

The fork branch is `snowbridge/ai-folder-icons` in
`vendor/filebrowser-upstream`, based on `snowbridge/dirsize`. Backend code is
under `foldericons/`; the route handlers are in `http/foldericons.go`.

## Enable the feature and scheduler

For a single interactive activation job, confirm crew-chief has the configured
model. In JSON-auth mode, first create the read-only scheduler account with the
same `Scope` and visibility rules. In `private-vpn-mtls` mode, no File Browser
password or extra app account is needed; the script issues a dedicated host
client certificate and uses Caddy's existing `snowbridge` proxy identity. Then
run:

```bash
./scripts/activate_filebrowser_folder_icons.sh
```

The script updates only the icon settings in the protected local env file,
installs the relay, builds and recreates the File Browser image, checks the
backend, runs one prefetch, and enables the Clockwork timer. It prompts for
sudo when needed. In JSON-auth mode it securely prompts for the scheduler
password; in mTLS mode it provisions an owner-only client key and certificate.
The script detects the mode from `access.local.toml`; pass
`--mode private-vpn-mtls` only if that file is missing or you need to override
it. Use `--skip-prefetch` to install the timer without the initial model call.
The step-by-step procedure below remains available when installing each part
manually.

1. Confirm crew-chief is running and has the model:

   ```bash
   bash ../crew-chief/scripts/status.sh
   bash ../crew-chief/scripts/pull_model.sh qwen3:14b
   ```

2. For JSON authentication, create a dedicated File Browser user named
   `folder-icons-scheduler` (or choose another name). Give it the same `Scope`
   and visibility rules as the normal browser user, with read access and no
   modify, execute, or admin permission. Set
   `FILEBROWSER_AI_FOLDER_ICONS_PREFETCH_USER` to that username. In
   `private-vpn-mtls` mode, use the existing `snowbridge` proxy user instead;
   Caddy authenticates the scheduler's client certificate and injects that
   username.

3. Install the crew-chief socket relay:

   ```bash
   sudo ./scripts/setup_crew_chief_relay.sh
   ```

4. Enable icons in `config/web/filebrowser/filebrowser.env.local` and select
   the custom image:

   ```text
   FILEBROWSER_AI_FOLDER_ICONS=true
   FILEBROWSER_IMAGE=localhost/filebrowser-snowbridge:ai-icons
   ```

5. Build the fork binary as your normal user, then package and deploy the
   image:

   ```bash
   git -C vendor/filebrowser-upstream switch snowbridge/ai-folder-icons
   ./scripts/setup_filebrowser_fork_workspace.sh --install-only
   (cd vendor/filebrowser-upstream/frontend && pnpm run build)
   (cd vendor/filebrowser-upstream && CGO_ENABLED=0 go build -ldflags "-s -w" -o filebrowser .)
   sudo ./scripts/build_filebrowser_fork_image.sh --skip-binary-build \
     --image localhost/filebrowser-snowbridge:ai-icons
   sudo ./scripts/setup_caddy_filebrowser.sh --mode private-vpn-mtls --recreate \
     --compose-file config/web/filebrowser/docker-compose.local.yml
   ```

6. For JSON authentication, copy the example scheduler credentials into the
   current user's private config directory, set the scheduler account password,
   and restrict the file to that user:

   ```bash
   install -d -m 0700 "$HOME/.config/snowbridge"
   cp -n config/web/filebrowser/folder-icons-scheduler.example.json \
     "$HOME/.config/snowbridge/folder-icons-scheduler.json"
   chmod 0600 "$HOME/.config/snowbridge/folder-icons-scheduler.json"
   ```

   The helper refuses a symlink, a config owned by another user, or a config
   readable by group/others. It sends credentials only to a loopback URL.

   In mTLS mode, the one-job activation script generates a dedicated host
   client certificate and stores its private key as mode `0600` under
   `~/.config/snowbridge/`; it copies the server trust CA there as
   `wiring-harness-server-ca.crt`. It sends the API request through Caddy at
   `https://files.snowbridge.internal`, where the client certificate is
   verified and the proxy identity is set to `snowbridge`. The scheduler
   verifies that HTTPS server certificate with the Wiring Harness CA at
   `~/.config/wiring-harness/certs/ca.crt`. This is a separate trust role from
   the Snowbridge mTLS client CA under `CADDY_DATA_DIR/mtls/`, which signs the
   scheduler's client certificate. Do not use the Snowbridge client CA as the
   HTTPS server trust root. The legacy Wiring Harness CA has no X.509
   `keyUsage` extension, so the helper disables Python/OpenSSL's additional
   strict-certificate policy for this connection while retaining CA-chain,
   certificate-time, and hostname verification.

7. Copy `config/clockwork/filebrowser-folder-icons.toml.template` to a local
   manifest, replace its `%h/git/util-repos/snowbridge` path with this checkout
   if needed, and install it through Clockwork:

   ```bash
   cp -n config/clockwork/filebrowser-folder-icons.toml.template \
     config/clockwork/filebrowser-folder-icons.local.toml
   clockwork install --manifest config/clockwork/filebrowser-folder-icons.local.toml \
     --target systemd-user
   systemctl --user enable --now snowbridge-folder-icon-prefetch.timer
   ```

The timer runs daily with a randomized delay. Its service logs the number of
directories scanned and icons generated. If it reports `more=true`, the share
has more than the per-run budget; the next run continues from the remaining
uncached folders. Each Ollama request is independently held by the ECU gate at
batch priority.

## Cache and operations

The service stores suggestions and manual overrides in
`/database/folder-icons.json`. The container receives the Ollama API only
through `/config/crew-chief.sock`; the relay targets the host's ECU gate.

- Reset a manual choice with **Use AI suggestion**. This reveals the cached AI choice
  without deleting it or triggering inference in a browser request.
- Disable icons with `FILEBROWSER_AI_FOLDER_ICONS=false` and recreate the
  container. Cached picks remain on disk.
- Remove the relay with `sudo ./scripts/setup_crew_chief_relay.sh --uninstall`.
- Reset all suggestions and overrides only while File Browser is stopped;
  deleting `folder-icons.json` while it runs can be undone by its in-memory
  store.
- Check relay status with
  `systemctl status snowbridge-crew-chief-relay.service` and scheduler status
  with `systemctl --user status snowbridge-folder-icon-prefetch.timer`.
- Model or relay failures are logged. A failed prefetch exits unsuccessfully
  so systemd records it; later timer runs retry uncached folders.

The default model is `qwen3:14b` with thinking enabled. A measured 10-folder
share-root batch took roughly two minutes on the host GPU. Change
`FILEBROWSER_AI_FOLDER_ICONS_MODEL` only to a model already pulled in
crew-chief.
